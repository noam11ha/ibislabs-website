# Approved launch retention schedule

Status: **Approved by Noam Hayoun on July 25, 2026**

| Record | Retention | Why this is proportionate |
|---|---:|---|
| Quiz answers, inferred profile, session ID, associated name/email | 24 months from collection | Long enough to evaluate profile demand and support a returning prospect; short enough to avoid indefinite retention of sensitive data |
| Funnel events, UTM/fbclid, user agent | 12 months | Covers seasonality and ad/funnel analysis without building a long-term activity history |
| Waitlist/non-customer lead | 24 months after last interaction | Allows launch follow-up while forcing stale leads out |
| Privacy/support case | 3 years after closure | Evidence of request handling and dispute resolution |
| Security logs | Up to 12 months unless investigating an incident | Security need with a defined default cap |
| Active-system deletion to backup expiry | Normally within 90 days | Allows normal backup rotation without restoring deleted data to active use |
| Orders, invoices, payment/refund and tax records | Applicable legal/accounting period | Required business records; access limited to that purpose |
| Minimal opt-out/suppression record | As long as needed to honor the opt-out | Prevents accidentally re-subscribing a person |

## Operational rule

A verified deletion or consent-withdrawal request overrides the default schedule unless a narrow legal, security, fraud-prevention, or dispute exception applies. When the exception ends, delete the record.

## Review trigger

Review this schedule after the first 90 days of real funnel data and annually thereafter. Shorten a period if the business is not actually using the data for its stated purpose. Any extension requires a documented purpose and a policy update before it takes effect.
